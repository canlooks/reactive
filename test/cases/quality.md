# 真实环境、非功能与端到端测试用例

以下为本轮交付的待执行测试设计。现有 jsdom、源码或tarball回归只能提供部分证据。执行前按 [测试计划](../TEST_PLAN.md) 记录OS、浏览器、Node、React、包散列、CPU/RAM以及数据规模；与 [基线记录](../BASELINE.md) 分开填报，禁止标为已通过。

## 1. 环境准备与判定方式

浏览器准备独立测试页面：安装本次tarball及匹配React/React DOM，使用测试团队实际采用的构建工具固定版本构建。页面提供输入、checkbox、select、状态展示、创建/卸载组件按钮、deferred读写的完成/失败按钮、调用次数面板。以 `qa:<run>:<case>` 为存储key；应用模块顶层或客户端启动流程只创建一次外部store。仅导入浏览器原生ESM图或构建工具的默认import路径，不混入Node条件桥。

localforage真实后端验证需使用独立实例，包装为StorageAdapter。先强制IndexedDB驱动并确认实际驱动标识，不能让其静默回退到localStorage后声称IndexedDB通过。异步完成观察由包装adapter暴露测试Promise/日志；不为库虚构ready/flush。

性能数据固定为：对象字段数1,000/10,000；读同一computed 100,000次；10,000次写入；数组length为1,000,000,000但仅3个自有索引；共享无环图与独立图各一份。每组预热3次、测量10次；记录中位数、P95（最近秩法，10项取排序第10项）、通知/getter/set次数、JSON字节数和堆大小。首轮建基线；后续同机比较若中位数或P95连续两轮劣化超过20%且绝对差超过2ms，登记性能回归供评审，此为拟定测试门槛，不是已有产品SLA。

## 2. 非功能缺陷判断

- 可确定的功能失败（重复订阅、maxActiveWrites>1、越写越多的等待任务、未停止回调、无限重试）直接报缺陷，不等待性能阈值讨论。
- 时间和堆大小受运行环境影响。保留原始样本、数据规模、GC/Profiler配置及基线；只有可复现劣化才判回归。不得承诺绝对零内存增长或指定毫秒内必GC。
- 大型共享图的JSON输出可能重复数据，统计节点数、输出长度两项；不只以唯一节点数推导序列化复杂度。
- 测试浏览器关闭时未完成写入属于已声明非保证项；若业务要求关页必达，记录为新增需求，不能把本版无flush接口当实现缺陷。
