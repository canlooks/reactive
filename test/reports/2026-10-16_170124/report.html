8. 缺陷详情与修复建议

S1已确认缺陷

D02 · 弃用 computed / 自动 getter 被长生命周期源永久保留

项目内容
类别 / 等级已确认缺陷 / S1
定位src/effect.ts:194–201；src/computed.ts:18–20；src/reactive.ts:66–73
触发条件在长期存活的 store 上重复创建、读取后丢弃 computed；或创建读取该 store 的 getter 对象并丢弃。无需保留外壳，也无需活动 effect。
预期业务已不再持有的派生对象及捕获载荷可以回收；依赖图不应让每次临时派生无限累积。
实际专用进程 12 轮跨事件循环 GC：1000/1000 computed 载荷、1000/1000 getter 根仍存活；释放唯一共享源后均变为 0。同条件 storage 两组各 1000 个根均回收为 0。两轮独立资源诊断均复现。
根因trackDep 将 computed 的 EffectNode 强引用加入源属性 Dep Set；节点强持有 fn/闭包。自动 getter 的 fn 还捕获 receiver，反向保留整个对象。WeakMap 以活跃源为 key 并不能释放它的强引用 value 图。堆路径为 source proxy → raw → targetDeps Map → Dep Set → EffectNode.fn → Context.payload。
修复建议优先调整派生节点的生命周期：源到无外部拥有者的 computed 节点使用可清扫弱引用；活跃 computed 外壳及真实消费者继续保证节点存活。自动 getter 同步采用该机制。不要只在 finalizer 的 holding 中强持有 fn/receiver；不要简单在最后 effect.stop 后清空所有 deps，这会使仍存活但暂时无消费者的缓存失效失灵。也可评估显式 scope/dispose，但这属于公共契约设计变更。
临时规避复用有限数量的 computed，避免在循环/重复渲染中临时创建并读取；需要手工生命周期时直接使用可 stop 的 effect/watch，或确保整个源及其派生图一起释放。
修复后回归保留源、丢弃外壳/最后消费者的 GC 与堆保留链；getter receiver 回收；仍活跃 computed 的惰性失效；分支回退、菱形依赖、stop、异常及 Suspense 的全部原用例。
